How Keccak Hashes a Message

From a plaintext message to a 256-bit hash, step by step with diagrams.

1. The Keccak State: A 1600-Bit Box

Keccak's internal state is 1600 bits, organized as a 5 × 5 grid of 64-bit "lanes." It's split into two regions:

The rate is where data enters and exits. The capacity adds internal complexity that makes the hash secure. Together they form the full 1600-bit state.

2. Hashing a Short Message (fits in one block)

Message: "Hello" (5 bytes = 40 bits). This fits in one rate block (136 bytes).

This entire process is one keccak-f call = one "instance" in the batch prover.

3. Hashing a Long Message (multiple blocks)

Message: 300 bytes. Rate = 136 bytes. So we need 3 blocks: Block 1 (bytes 0-135), Block 2 (bytes 136-271), Block 3 (bytes 272-299 + padding).

4. What One keccak-f Permutation Does (One Instance)

Each keccak-f takes 1600 bits in and produces 1600 bits out, through 24 identical rounds. Each round applies 5 steps to the 5×5 grid of 64-bit lanes:

After 24 rounds of this, every output bit depends on every input bit in a complex, unpredictable way. This is what makes Keccak a secure hash function.
