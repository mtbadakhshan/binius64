Three Keccak GKR Approaches

k=1 (standard), k-flat (sequential grouped), k-parallel (lockstep batched)
All illustrated with k=4. Each round is a fused chi+iota+theta+rho+pi transition.

Round & Sumcheck Structure (k=4, n_groups=6)

k=1: 24 sequential sumchecks

k-flat (k=4): 6 sequential sumchecks

k-parallel (k=4): 4 batched sumchecks

Complementary View (k=6, n_groups=4)

With k=6: flat has 4 sumchecks (same as par-4), parallel has 6 sumchecks (same as flat-4). The flat/parallel roles swap.

k-flat (k=6): 4 sequential sumchecks

k-parallel (k=6): 6 batched sumchecks

Common GKR Circuit Input / Output

All three approaches operate on the same data and produce the same result type.

Circuit Input trace: CompactTrace {
  round_inputs: Vec<Vec<[u64; 25]>>, // 24 entries, S_0..S_23
  final_output: Vec<[u64; 25]>,      // S_24
}

The verifier also samples from the Fiat-Shamir channel:
bit_challenge: F, high_point: Vec<F>, lane_weights: [F; 25]

Circuit Output BitIndexedEndpointClaims<F> {
  output_claim: BitIndexedMixedClaim<F>, // claim on S_24
  input_claim:  BitIndexedMixedClaim<F>, // claim on S_0
}

Each BitIndexedMixedClaim contains bit_challenge, high_point, lane_weights: [F; 25], lane_evals: [F; 25], mixed_eval: F.

k=1: 24 Sequential Sumchecks

protocol.rs::prove() / verify()
Each sumcheck = one FusedRoundReduction (chi+iota+theta+rho+pi).

k-flat (k=4): 6 Sequential Sumchecks

protocol.rs::prove_grouped() / verify_grouped()
Each sumcheck = one GroupedRoundReduction batching k transitions.

k-parallel (k=4): 4 Batched Sumchecks

parallel_groups.rs::prove_parallel() / verify_parallel()
Each sumcheck batches all 6 groups at one layer via BatchedParallelProver.

Data Flow: How Each Approach Chains Rounds

k=1
  1. Channel samples bit_challenge, high_point, output_weights
  2. Build output_claim on S_24
  3. for round in (0..24).rev():
  4. prove_round_from_words(round_inputs[round], FusedRoundReduction{..}, channel)
  5. --> FusedRoundOutput { reduced_high_point, input_evals }
  6. Build new claim from channel.sample_array() + input_evals
  7. Return { output_claim, input_claim }
k-flat
  1. Channel samples bit_challenge, high_point, output_weights
  2. Build output_claim on S_24
  3. for group_idx in (0..6).rev():
  4. Sample transition_weights (k-1 values for intra-group zerochecks)
  5. Batched poly: fused_last(x) + Sigma tw[r] * (fused_r(x) - S_{r+1}(x))
  6. Residuals fused_r(x) - S_{r+1}(x) vanish on booleans (zerocheck)
  7. --> GroupedRoundOutput { reduced_high_point, input_evals }
  8. Return { output_claim, input_claim }
k-parallel
  1. Channel samples bit_challenge, high_point
  2. Build 6 group_claims on S_4, S_8, ..., S_24
  3. for layer in 0..4:
  4. Sample batch_weights (6 values)
  5. Layer 0: also sample residual_weights (5 values)
  6. prove_single_mlecheck(BatchedParallelProver{..}, channel)
  7. Update all 6 group_claims from input_evals
  8. At layer 3, g=0: return { output_claim, input_claim }

Memory Pressure: Why k-parallel Can Be Slower at Large Batches

All three approaches do the same total work (24 fused chi+iota+theta+rho+pi evaluations per instance). The difference is how many state arrays each sumcheck must scan.

At small batch sizes where data fits in cache, all approaches are competitive. At large batch sizes (h >= 2^14), the per-sumcheck working set of k-parallel can exceed cache, causing slowdown despite having fewer sumchecks. Use compare_provers to measure on your hardware.

Each Approach Wins on a Different Metric

Optimize for... Best approach Why
Fewest PCS commitments k=1 Only S_0 + S_24 need commitments. All intermediates virtual.
Smallest working set per SC k=1 1 array per sumcheck. Best for large batches.
Shallowest Fiat-Shamir depth k-parallel 4 x log(h) rounds. Best for recursive verification.
Smallest transcript (no PCS) k-parallel Fewest sumcheck proofs written to transcript.
Virtual intermediates + parallelism k-parallel Only approach with both + provable boundary consistency.
Intra-group zerocheck k-flat transition_weights enforce fused(S_r) = S_{r+1} within each group. Residuals vanish on booleans.
Inter-group boundary zerocheck k-parallel residual_weights enforce fused(S_{4g+3}) = S_{4(g+1)} at layer 0.
Fewest Gruen32 initializations k-parallel Only 4 sumcheck rounds vs 24 (k=1) or 6 (k-flat).
Simplest implementation k=1 One FusedRoundProver, no batching or boundary logic.
